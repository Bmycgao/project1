# 协议打印：入口与文件职责

打印包含两条主要流程：编辑模板，以及把模板和协议数据组合成打印结果。

## 先找入口

| 想修改什么 | 文件 |
| --- | --- |
| 协议列表打开的打印预览、PDF 导出、打印 | `print-preview-dialog.vue` |
| 粘贴或查看打印数据 JSON | `print-data-json-dialog.vue` |
| 模板设计器的加载、保存、撤销、预览 | `designer/agreement-print-designer.vue` |
| 画布拖动、缩放和元素选择 | `designer/document-canvas.vue` |
| 数据绑定、列编辑、显隐和筛行 | `designer/print-inspector.vue` |
| 字体、颜色、表格边框、恢复默认样式 | `designer/print-style-panel.vue` |
| 字段列表和默认列 | `data/fields.ts` |
| 默认模板、加载与保存 | `template/agreement-template.ts`、`template/template-store.ts` |
| 表格计算、合并和打印结果处理 | `runtime/prepare-template.ts`，再跟进它调用的模块 |

## 目录职责

```text
print/
├─ designer/                    设计器、画布、属性面板和编辑对话框
├─ data/                        协议转打印数据、字段、格式、样例、脱敏
├─ template/                    默认模板、存储、元素定位和模板修改
├─ runtime/                     公式、筛行、合并、分页、回流、水印
├─ engine/                      hiprint 初始化、依赖和组件注册
├─ print-preview-dialog.vue     业务打印入口
├─ print-data-json-dialog.vue   设计和预览共用的数据输入框
└─ types.ts                     打印数据类型
```

测试跟随被测试模块放置，例如 `runtime/print-paper.test.ts` 检查纸张和分页。不要创建汇总所有内部函数的 `index.ts`；调用方直接导入具体模块，便于查找实现。

## 打印时，数据经过哪里

1. `print-preview-dialog.vue` 接收协议详情或用户输入的数据。
2. `data/build-print-data.ts` 将协议详情转换成打印数据。
3. `template/template-store.ts` 按编码加载模板，`data/print-sensitive.ts` 根据权限对数据脱敏。
4. `runtime/prepare-template.ts` 整理模板和数据，处理公式、显隐、表格规则及排版。
5. `runtime/document-renderer.ts` 按实际内容排版分页，`engine/document-print.ts` 将同一结果交给预览、打印和 PDF。

查“界面数据正确但打印不对”的问题，先看第 4 步的输入输出，再检查具体规则模块。

## 编辑时，怎样写回模板

`document-canvas.vue` 和属性面板通过设计器维护完整的模板 JSON。样式面板接收选中元素，提交 `patch` 事件；`print-inspector.vue` 用 `patchElementOptions()` 写回模板，再通过 `canvasPatch` 通知设计器更新。

因此，调整字体、颜色和边框时，只需从 `print-style-panel.vue` 开始。它自己管理表单草稿和选中元素切换，不依赖整份模板、接口或本地存储。

保存时直接使用设计器维护的完整 JSON，不再经过旧的 hiprint `getJson` 字段恢复流程。计算公式、颜色、合并等扩展信息仍保存在模板中，相关测试覆盖保存后的 JSON 往返。

## 两个设计入口都在使用

- `designer/index.vue` 是后台菜单通过字符串路径加载的独立协议设计器。没有静态 `import` 不表示它没用；此入口使用本地模板保存。
- 系统管理的 `system/print-template/edit.vue` 复用 `agreement-print-designer.vue`，通过模板管理流程保存到服务端。

不要只根据函数上的旧注释删除本地保存逻辑，也不要直接改变已有路由组件的路径。深拷贝统一使用协议目录下的 `clone.ts`；纯计算模块不需要为了深拷贝而导入存储或 API 模块。

## 文档流布局（默认）

正文使用普通文档流和 flex 行列，文字实际高度由浏览器计算。同一行按最高内容占位，后续行自然顺延；正文无需回流组，也不再使用绝对坐标定位。

- 从左栏添加元素或字段时，按住拖动超过少量距离便显示跟随提示和纸面插入线，松手只新增一次；Esc 或拖出纸张取消。轻点仍按单击添加处理。文档流模式的左栏添加、纸面元素移动和两个拖动手柄统一使用指针事件，不依赖浏览器原生 HTML5 拖放；浮动手柄、列分隔线覆盖处也能识别纸面落点。
- 选中元素后，蓝色选中框贴着实际文字或表格。拖动「调间距」手柄时，绿色虚框预告落点并显示 pt / mm 距离；上拖可收紧到 0。达到最小间距后若需要跨过上一段，应改用「排序」手柄。
- 直接拖动未选中元素时，拖动期间不改变选中或插入工具条，松手后才提交并选中该元素，避免原生拖拽被布局更新取消。拖动结束产生的多余点击会被拦截，下一次正常点击不受影响。
- 拖动「排序」手柄时，蓝色插入线显示前后位置，空白处也会吸附到最近一行；靠近目标左、右边缘时提示插入它的左、右侧；同行换位保留各元素宽度，新加入同行时均分宽度。按 Escape 或拖出纸面可取消，拖动过程不写入模板，松开才产生一次修改。
- 选中同行元素后，拖动列间蓝色分隔线可调节相邻两列宽度，其他列不变；拖动中实时换行并显示百分比，松手后重新分页并记作一次修改，Escape 取消。分隔线获得焦点后可用左右方向键微调 1%，按住 Shift 调整 5%。
- 画布顶部的排版工具条提供向左/右换位、独占一行、宽度、靠左/居中/靠右、上方间距（mm）及清除间距。调整后保持选中；可用设计器撤销恢复。同行修改宽度数值会按比例调整其他列，分隔线则只影响相邻两列。
- 「上方间距」只调整当前元素。旧模板的整行间距和元素留白合并为同一个可编辑值；首次调整时将共享间距转为各元素自己的间距，同行其他元素的视觉位置不变。一般上限 200pt（约 70.6mm），旧模板更大的间距可逐步收紧。
- 「占正文宽度」控制宽度；独占一行时可选择靠左、居中、靠右。例如盖章区可独占一行靠右，或与签字同行后单独增加上方间距，正文增长时仍然跟随下移。
- 「隐藏后 → 移除空位」会移除该元素。整行隐藏后，不再占据该行高度及段前间距；同一行仍有可见元素时，保留它的列位置。「保留空位」按模板原来的设计高度保留空白占位。
- 「尽量与下一段同页」适合章节标题，减少标题单独留在页尾的情况。
- 正文超过纸张可用高度自动续页。普通段落尽量整段换页；超长段落按实际换行拆分；长表按行续页并重复表头，单个单元格超过一页也能拆分保留文字。盖章和签字跟随正文，正常情况下整行换页。
- 「新增手工区段」和页面隔断明确要求后续内容另起一页。自动续页不会写入模板，不会因为更换样例数据改变保存的区段数。
- 正文左右和上边距为 20pt，下边距 40pt。页码、水印属于页面装饰，仍可使用纸面定位。

旧模板首次打开或打印时，由 `runtime/document-layout.ts` 把坐标转换为行、列宽、缩进和间距，写入 `options.agreeDocument`。保存后直接使用这些结构信息；原来的坐标和分组信息保留作兼容信息，不再控制正文排版。历史自由排版模板应在转换后检查同行关系及间距，调整满意后保存。

`runtime/document-renderer.ts` 负责共享的 DOM 渲染、字体测量和分页，画布、预览、打印及 PDF 使用同一份排版规则。`engine/document-print.ts` 只借用 hiprint 的打印及 PDF 输出能力。旧的 `canvas-stage.vue` 和回流模块保留给旧版内部调用及回归测试。

## 统一表格入口与编辑方式

左侧统一选择“表格”，单击或拖入纸张后选择起步方式；取消选择不会添加元素，拖入后的实际插入位置保持不变。

- **明细表**：一个数组按列绑定并重复成行，适合房屋、补偿、奖励清单。保留多层表头、筛行、列计算、条件颜色、合并与表尾；分页可重复表头。
- **自由表单**：按单元格绑定，可混排固定信息与多个数据源的明细。默认附带协议编号、日期、房屋明细和合计示例；建筑面积使用 `row.buildArea`。

两种方式共用字体、颜色、适用的边框设置、字段选择和显示格式。整表外观统一在侧栏“样式”修改，显示条件统一在“规则”修改，弹窗不再重复。明细表按“数据来源、列与表头、合计与备注”组织设置；自由表单按“单元格、当前行、当前列”组织设置，数据源属于当前行。只展示当前方式实际支持的设置。

表头按列范围分组收进高级设置；样例默认折叠。合计在“合计与备注”勾选数值列，使用筛选后的全部明细，不是协议总金额。备注一键添加整行，自定义表尾保留在高级入口，按格点选编辑。画布合并工具跟随选区末端显示，不再占据页面顶部。

编辑窗口内先修改草稿，样例使用与打印相同的表格渲染规则，最多显示 12 行；完整分页使用快速预览。“取消”或关闭窗口丢弃草稿，“应用到画布”一次提交，设计器可以一次撤销；应用后仍需保存模板。画布侧栏直接修改样式/显隐仍即时生效。

两种方式保留原有模板数据结构，不自动相互转换。自由表单中的列标题目前是固定行，不会在续页重复，不能代替所有明细表功能。

自由表单配置：

- 固定格：选择“固定文字”填写标签，或选择“绑定字段”填写 `agreementNo`、`signDate` 等主字段；也可使用字段选择器。
- 动态行：在“本行数据源”选择 `houses`、补偿或奖励等数组。本行每个格子可绑定 `row.address` 等当前记录字段，主字段仍可直接绑定。一个表单可包含多个独立的动态行。
- 公式：序号使用 `index + 1`，明细金额可使用 `row.quantity * row.price`，汇总使用 `SUM(houses, "buildArea")`；金额、日期、大写金额等通过单格“显示格式”配置。
- 结构：点击格子，按住 Shift 点击另一个格子选择矩形后合并；支持固定区域横纵合并，以及动态行横向合并。合并显示左上格内容，拆分恢复被覆盖格内容。增删行列会调整合并范围。
- 动态行没有数据时，可保留一行空白或移除本行。后面的固定行、其他明细及合计自然顺延；所有行都被移除时，整张表不显示并遵循元素补位设置。
- 点击“应用到画布”更新组件，再保存模板；取消不会修改模板。整张表保留现有画布拖动、宽度调整、显隐、样式和分页能力。

配置保存在 `options.agreeFormGrid`。`runtime/print-form-grid.ts` 将运行时副本编译为原生表格列、独立数据数组、合并与样式信息，文档流画布和打印使用同一份数据。旧的普通表格不会被转换。

边界：一个动态行对应一条记录，不支持跨动态行的纵向合并或单条记录重复多行块。长表按文档流渲染器续页；表单内部的章节标题、明细列标题是普通固定行，暂不自动在续页重复。

## 检查命令

在仓库根目录运行：

```sh
pnpm exec vitest run apps/web-ele/src/views/biz/agreement/print
pnpm --filter @vben/web-ele typecheck
```

涉及界面交互时，还需检查：切换选中元素、修改样式、恢复默认、保存重开、快速预览和打印。模板 JSON 的字段结构保持兼容，目录整理本身不需要迁移已有模板。
