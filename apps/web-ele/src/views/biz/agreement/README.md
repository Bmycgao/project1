# 协议业务：从哪里开始看

本目录当前承担流程、页面配置和打印的模拟业务案例。协议字段、状态、编号和旧列表审核规则仅属于该案例，不能据此推导正式业务制度或平台默认规则。当前仍有协议耦合，详见[范围与业务接入盘点](../../../../../../docs/platform-scope-and-coupling-audit.md)；其中整改方案尚未替代下文的现有行为。

先打开你要修改的页面，再沿着事件和数据查找相关文件，不必从框架底层开始。

| 想修改什么 | 从哪里看 |
| --- | --- |
| 列表查询、勾选、打印入口 | `list/index.vue` |
| 详情加载、编辑与保存 | `detail/index.vue` |
| 新增、审核、跳转等按钮操作 | `actions.ts` |
| 某种场景的列、按钮、模块配置 | `config/resolve-runtime.ts`，再看 `config/scenes.ts` |
| 字段能否看到、能否编辑 | `access/field-access.ts` |
| 在 Vue 组件里使用字段权限 | `access/use-field-access.ts` |
| 详情模块的可见性、顺序和布局 | `access/module-access.ts` |
| 模块内部的字段和默认值 | `config/module-inner-config.ts` |
| 房屋、补偿、奖励等具体表单 | `modules/` |
| FormCreate 的规则转换和绑定 | `fc/` |
| 打印设计、预览与计算 | [print/README.md](./print/README.md) |

## 目录职责

```text
agreement/
├─ list/         列表页面
├─ detail/       详情页面
├─ modules/      房屋、补偿、奖励等业务区域
├─ components/   协议页面共用的界面组件
├─ config/       场景配置、默认配置及配置整理
├─ access/       字段和模块权限；Vue 中的权限状态传递
├─ data/         演示数据和样例构造
├─ fc/           FormCreate 适配
├─ print/        打印功能
├─ actions.ts    按钮操作
├─ types.ts      协议数据类型
└─ clone.ts      共用的 JSON 深拷贝
```

新协议使用空白草稿初始化，只有编号、草稿状态和未签约标记等系统值；业务资料由用户填写。新增后直接进入编辑，可先保存不完整的草稿，提交复核时再校验必填项。接口失败时列表、详情和打印入口均明确报错，不生成示例业务资料，也不把本页内存当作保存成功。

页面只展示一个协议编号。新建时默认生成 `LL-年份-四位流水`（例如 `LL-2026-0001`，超过四位自动扩展）；从未提交过且未签约的草稿可修改，编号必填、最多64个字符，不能与其他协议的现用或历史编号重复。提交复核或发起配置流程后锁定，驳回不会重新解锁；整页和分模块保存使用同一规则。

内部 ID 不展示为第二个编号，详情存档、新详情链接、批量动作及流程关联均使用内部 ID。改号同步列表、协议头、权利人记录及打印取数，原编号保留为历史别名，旧链接继续定位同一份协议；历史编号不会分配给其他协议，删除记录后也保留编号占用。旧存档在读取时兼容迁移，首次写入新版存档前自动备份原文件。已有编号不批量改写，需要调整的旧长编号可在草稿中手工修改。

`data/mock-data.ts` 仅供演示预览和打印样例使用。后端已有的内置演示记录仍保留样例详情，新增协议与缺失字段补齐均使用空白默认值。

演示状态统一由 `apps/shared/agreement-demo-status.ts` 维护，默认详情表单、列表筛选及列表/详情标签颜色共用该来源。包含历史已有的“项目经理已审核”“签约已确认”等值；“已签约”和“签约已确认”保留为不同的原始值，不自动合并。旧内置 FC_BASIC 模板启动时仅补缺失选项，保留自定义字段、标签及其他选项；用户自建模板不批量扩展。旧页面配置或流程快照未包含当前值时，仅在运行时补充当前选项，保证能显示和原值保存。显式配置的场景状态筛选范围继续有效。这些展示值不定义流程阶段或正文编辑权限，流程结束也不会据此自动更改业务状态。

协议资料由后端统一保存至 `apps/backend-mock/data/agreements.json`，整页保存、分模块保存和流程回写共用同一持久化入口，重启后恢复。该文件包含列表与详情，不能只备份页面配置代替业务数据备份；具体存储位置及部署限制见 [后端说明](../../../../../backend-mock/README.md)。

## 第一条阅读路线：列表查询

1. 在 `list/index.vue` 看 `keyword`、`statusFilter`：查询条件存在哪里。
2. 找到 `loadList()`：怎样把条件传给 `getAgreementList()`。
3. 接口实现在 `src/api/biz/agreement.ts`。
4. 返回结果写入 `tableData`，再交给模板中的 `ElTable`。
5. 最后看 `loadRuntime()`：列和按钮如何随场景变化。

页面配置优先从后台加载，本地 `config/scenes.ts` 提供默认场景；具体整理过程集中在 `config/resolve-runtime.ts`。修改配置来源时先读这个入口，避免在不同页面各写一套判断。

## 后续开发约定

- 普通界面直接使用 Vue 和 Element Plus；复用项目已有的请求、权限和布局能力。
- 只被一个组件使用的小函数可以留在组件内；多个地方共用或有独立业务含义时再提取。
- 新文件放进对应职责目录，避免重新把配置、权限和打印逻辑平铺到根目录。
- `*.test.ts` 是回归测试，通常不进入正式页面运行代码。修改相关规则时运行测试，不要为了减少文件数量删除测试。
- `config/module-inner-config.ts` 仍集中保存多类模块的默认配置和兼容处理。后续修改某类模块时，可按业务模块逐步拆分，保持配置数据结构和旧配置兼容。

## 详情视图布局

页面配置的 `modules` 以稳定的 `key` 引用业务模块，`enabled` 控制显隐，`region` 选择 `content`（直接展开）或 `tabs`（标签页），`order` 在区域内排序，`span` 决定内容区的 24 栅格占宽。旧配置未填 `region` 时，基础信息默认为内容区，其余模块默认为标签页。移动、改名和隐藏均不更换标识或删除业务数据。

`components/detail-layout.vue` 是详情与设计器预览共用的布局，`components/detail-module.vue` 统一注册内置及自定义表单／表格。标签切换使用 `v-show` 保留未保存内容。保存整页只合并已展示模块返回的值，保留隐藏模块及其他自定义模块的数据。

页面设计器集中维护模块属性，字段由表单模板维护。预览使用示例数据和实际业务组件，不保存业务资料；保存配置前检查模板是否可用、类型是否匹配。此配置是页面基础视图，流程节点通过稳定的模块标识叠加隐藏、只读或可编辑策略，不改写共用页面配置。

流程发布时会冻结节点引用的页面布局、表单模板和字段限制。运行时先应用页面及角色权限，再应用节点模块和字段权限；限制只能继续收紧。接口返回值按同一份生效视图裁剪，隐藏资料不会下发，提交时也会按白名单合并，保留本节点无权修改的数据。填报节点的“继承”默认为可编辑，审批节点的“继承”默认为只读；审批节点只有显式设为可编辑的模块或字段才可修改。

普通协议详情与流程办理使用不同的编辑入口。当前协议字段和状态均为演示数据，待复核、待生效、已签约等文案，以及内部 status/isSigned 均不作为正文编辑锁定依据。没有在途流程时，详情按角色和模块权限编辑；存在运行或挂起的关联流程时，普通详情只读，修改通过流程当前允许的办理节点进行，驳回后也在退回的填报节点修改重提。所有关联流程均已完成或已终止后释放流程占用，历史审批记录继续保留。未知状态或流程资料缺失时保留保护，不自动解锁。详情接口返回 `entryEditable` 与 `entryReadonlyReason`，这些字段只控制普通详情，不能代替流程自身的节点权限。未来真实业务的归档或签约锁定规则需明确接入，不能从演示状态推断。

全部保存、分模块保存、旧版提交复核、列表通过/驳回及删除接口均检查服务端最新流程占用，客户端伪造“草稿”、编辑路由参数或保留旧页面不能绕过在途流程限制。批量操作先检查全部选中项，存在不允许当前操作的记录时整批拒绝。有历史流程的协议仍不可直接删除，避免丢失流程关联。普通保存允许暂存不完整资料，不按“草稿/非草稿”切换必填校验；提交复核仍校验当前可见模块。旧版列表审核结果保护保留在该演示动作中，不作为正文编辑限制。协议编号在提交或发起流程后持续锁定，恢复正文编辑不会恢复改号。流程发起时另存持久化接管标记，作为实例资料缺失时的保护依据；实例落盘失败会撤销本次新增的标记。成功后重启仍保留标记，但实际历史流程均已完成或已终止的协议无需清理标记即可恢复正文编辑。
