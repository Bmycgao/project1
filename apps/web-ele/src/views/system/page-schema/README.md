# 页面配置：列表与详情分离

管理入口按用途分为「列表页面」「办理详情」「公共列方案」。列表通过 `detailSchemaId` 实时引用独立详情；详情维护模块、模板和布局，流程发布时冻结快照。

## 第三阶段：三栏详情编排

已有独立详情打开后直接进入「详情编排」，新建详情先填写基础信息。左侧选择、搜索或添加资料模块；中间按所选模板显示字段结构，内容区直接展开，标签页区切换查看；右侧设置显示、名称、模板、区域与宽度。

可以拖动模块跨区域或排序，隐藏模块也可从左侧拖回画布。标签页始终整行显示，移回内容区恢复原宽度；移动、隐藏或改名不改变模块标识和业务数据。

「查看字段 / 复制」只读展示模板字段。创建独立副本会实际保存一份新模板，复制字段、校验和模板选项后选中到原模块；页面关联需保存后生效。可在新窗口打开对应模板编辑器修改字段，返回后刷新模板。副本保留在模板库，即使取消页面编辑也不会删除。

「配置检查」列出缺失、停用、用途或类型不匹配、空规则的模板并定位模块。预览与保存复用同一套模板检查；预览会刷新模板资源并使用当前未保存布局、模板字段和本页字段限制，支持桌面与窄屏。字段示意不执行模板脚本，实际组件效果在只读预览中查看；流程节点权限仍在流程办理时叠加。正式详情共用的 FormCreate 运行组件在窄容器中将字段改为单列，避免半行模块或窄屏预览中标签与输入框挤在一起。

## 第二阶段：列表引用与旧场景拆分

新建业务列表时，在「关联详情」选择已启用的独立办理详情。列表只保存列、数据范围和动作，布局在独立详情中维护；多个列表可共用同一份详情。

原有内嵌详情的业务场景显示「兼容配置」提示，继续保留旧编辑能力。迁移入口：列表页面 → 去配置 → 关联详情 → 拆出独立详情并关联。

拆分操作以服务端已保存的场景为准：生成独立详情，将原列表改为引用，保留列表编号、场景、公共列方案、动作和历史。写入同一个配置文件时使用原子替换，失败回滚内存；重复请求返回已有关联，避免重复创建。拆分前的配置进入历史，可以回滚；回滚后已拆出的详情仍保留，供其他引用继续使用。

流程草稿原来引用列表的，也会在新发布时解析关联详情，冻结实际详情编号和来源列表编号。已发布的历史快照保持原内容。新流程建议直接选择独立办理详情。

关联详情缺失、停用或绑定模板不可用时，业务详情会明确报错，不自动换成默认五个模块。列表列规则与详情字段规则独立；拆分会保留旧场景及公共列方案的字段限制。

## 配置一份独立办理详情

1. 页面配置 → 办理详情 → 新建办理详情。
2. 填写内部编码、页面名称，在「详情编排」中启用模块、绑定类型匹配的表单模板并调整布局。
3. 保存。无需场景码、公共列方案、列表列、查询条件或列表按钮。
4. 打开流程设计器 → 流程属性 → 流程默认详情页，选中该配置。也可从流程属性的新建入口打开配置页，保存后返回并点击「刷新资源」。
5. 人工节点默认继承，可以继续使用原来的节点覆盖、模块和字段权限设置。流程发布时冻结详情与表单模板；后续修改只供草稿及新版本发布使用，已有版本继续使用原快照。

详情模块读取同一条协议数据。表单模板定义模块字段，页面配置负责组装布局，流程节点设置办理权限。打印仍由打印模板负责，此阶段没有迁移打印绑定。

## 使用位置与删除

每行的「使用位置」及编辑器同名页签展示菜单、引用公共列方案或独立详情的列表、流程草稿默认页和节点覆盖引用。已发布及已停用流程按照实际冻结快照单独统计，不按当前草稿字段推断。

「未挂菜单」只表示没有菜单关联，不表示未被流程使用。使用位置加载失败会单独报错。删除前前后端均检查引用；仍有实时引用则阻止删除，先到对应配置解除关联。仅剩冻结快照时可删除源配置，历史流程保留快照。

## 兼容范围

- `schemaKind=detail` 是新增的独立办理详情，列表入口和菜单选择器不会把它作为业务列表。
- 原 `entity` 和 `scene` 配置保留在列表页面，`template` 归入公共列方案。旧场景继续保留原有列表和详情编辑能力，也继续可供流程引用。
- 已保存配置锁定用途，避免把已挂菜单的列表直接改成详情而破坏引用。新建时选择合适用途。
- 旧场景由操作员显式拆分，不在启动时自动迁移。独立详情及已关联列表跳过旧模块补全逻辑，重启不会重新生成内嵌详情。

相关验证：共享用途校验、独立详情保存、编辑器交互、使用位置统计及流程发布冻结测试。
