## 本次发现并修复的问题

空表单保存后，接口可能返回集合字段值为 `null`。Element Plus 穿梭框要求数组，收到 `null` 后触发 `.includes` 异常，使整个表单区域消失。

在 `apps/web-ele/src/views/workflow/node-form.vue` 的渲染数据投影中，将集合控件（`choiceList`、`table`）的 `null` / `undefined` 映射成空数组。仅处理控件视图所需的空值，不把错误的非空标量转换为合法数据，也不改变字段写入权限。

`node-form.test.ts` 增加实际 FormCreate 引擎回归场景：保存期间切换 busy 状态、回填 `items: null` 和 `rows: null`，验证穿梭框和明细表仍渲染、返回空数组、必填校验仍失败，随后可继续回填并切换只读。

验证命令：

```powershell
node node_modules/vitest/vitest.mjs run apps/web-ele/src/views/workflow/node-form.test.ts --reporter=dot --maxWorkers=1
# 1 个测试文件、1 个集成测试通过

# 在 apps/web-ele 中执行
node ../../node_modules/vue-tsc/bin/vue-tsc.js --noEmit --skipLibCheck
# 通过
```

测试过程存在第三方设计器 sourcemap 警告及预期的必填校验日志，不影响测试通过。

## 数据行为与范围

当前实现会将流程扩展字段持久化到协议的流程字段数据中，因此相同协议再次发起、使用相同字段标识时，可能读取到先前填写的值。本次 V2 初次进入即读取到了 V1 保存过的三个字段值。这属于当前数据存储行为；发布快照冻结的是表单配置，不代表新实例的数据必定为空。需要每次发起都重新填写的业务，应另行明确初始化策略。

本次浏览器验收覆盖时间、输入框、静态穿梭框及两种页面模式的核心闭环；明细表空值另有集成测试覆盖。未逐项遍历所有设计器控件、所有角色、并行会签或第三方数据源，不能据此宣称这些场景已全部验收。

第二步结束时未执行 Git 暂存或提交；第三步收尾将流程、页面权限和运行时配套改动整理为同一版，打印设计器功能及个人界面设置另行保留。
