## 2. 各个配置入口分别负责什么

| 内容 | 负责的问题 | 示例 | 不应隐含的业务规则 |
| --- | --- | --- | --- |
| 业务数据及字段说明 | 一条记录有哪些字段、明细、类型和稳定标识 | 名称、申请金额、物品明细 | 看到某个字段名称就自动识别业务生命周期 |
| 表单模板 | 字段如何输入、展示和校验 | 文本、金额、日期、明细表 | 新增同名控件就能写入任意业务表 |
| 页面配置 | 页面由哪些模块组成，顺序、布局、列表列和入口是什么 | 基础资料在上、明细在标签页 | 页面布局本身决定审批路线或签约结果 |
| 流程节点配置 | 谁办理、允许哪些动作、看哪些字段、提交后去哪里 | 填报可编辑，审核只读并填写意见 | 审核节点的名字自动对应一个业务状态 |
| 打印模板 | 已取得的数据如何排版输出 | 主字段、重复明细、页码、金额格式 | 打印完成就自动视为已签约 |

页面配置有用途：它提供办理页面的基础视图；节点叠加权限，打印模板引用相应业务数据。三者需要稳定字段标识和明确数据映射，但不必强求编辑页面结构与打印结构完全相同。

当前页面配置、预览和部分字段目录仍使用协议模块，尚未成为任意业务都可直接接入的页面平台。自定义节点补充表单能增加办理资料，也不等于已经支持独立创建、存储第二种业务记录。

## 3. 两种状态和两类编辑限制

### 流程状态

`running / suspended / completed / terminated` 描述一次流程实例正在办理、挂起、结束或终止。它们由引擎维护，可以作为平台规则。

### 业务状态

“草稿、告知单、待复核、待生效、已签约、组长已复核、项目经理已审核”等是演示协议的业务值。真实字段名称、取值和变化时机没有确认；“已定稿”也不是当前已有的同名字段或状态。

目标规则如下。这是后续解耦的设计约束，并非宣称当前代码全部符合：

| 情况 | 平台负责的限制 | 业务系统负责的限制 |
| --- | --- | --- |
| 没有在途关联流程 | 不因历史流程而增加永久正文锁；仍检查用户权限 | 是否已归档、作废、签约，以及允许哪些更正 |
| 有运行中的关联流程 | 普通入口防止绕过审批；办理页按当前任务、节点和字段权限写入 | 字段类型、取值、业务约束 |
| 流程挂起 | 保留本流程占用 | 继续执行原有业务约束 |
| 流程完成或终止 | 释放本流程占用，保留历史；其他在途流程的限制继续生效 | 依据已确认规则决定记录是否还可编辑 |
| 完成后需归档、锁定或改状态 | 执行显式配置、已注册且有权限的业务动作 | 提供合法状态变更、失败回滚和更正入口 |

业务状态没有接入定义时，不用模拟的中文文案猜测记录是否已定稿。存在未知流程状态、损坏文件或缺失历史时，应提示异常并保留保护，不能据“没看到待办”直接清除锁。

流程结束后修改业务记录时，还要明确历史查询和打印读取的是“当前资料”还是“当时审批资料”。需要正式审批追溯的业务应保存资料快照及版本；当前流程表单配置已冻结，但不等于整份业务资料已按审批版本完整冻结。快照需求单独验收。

### 状态来源不一致的修正

| 修正前来源 | 原内容 | 原影响 |
| --- | --- | --- |
| 后端演示列表种子 | 含“签约已确认”“项目经理已审核” | 列表能显示详情选项中没有的值 |
| 前端列表默认筛选 | 告知单、待复核、组长已复核、签约已确认、草稿 | 缺少部分已有行状态，筛选不完整 |
| 默认详情表单 | 草稿、告知单、待复核、待生效、已签约、组长已复核 | “已签约”与列表“签约已确认”命名不同 |
| 后端详情内部状态 | 类型列出draft/review/submitted；旧列表审核写入approved | 类型与写入不一致，且与展示状态不是同一个字段 |

展示字典已统一到 `apps/shared/agreement-demo-status.ts`，默认表单、列表筛选及列表/详情标签颜色共用该来源。旧内置模板补缺失选项；旧页面/流程快照仅在运行时补充当前缺失值，保留自定义选项与原快照。显式配置的场景筛选范围继续生效。已有存档中的“已签约”“签约已确认”等值不自动合并或改写，未知值按原文显示，不增加正式审批阶段，也不参与正文锁定。内部状态类型与旧审核路径仍需在后续接入改造中整理。

## 6. 最小接入方案及实施顺序

以下是建议契约，当前代码尚未实现统一注册机制。第一轮只包装已有协议接入，并预留第二个简单测试业务；避免同时重写所有页面和存储。

| 接口职责 | 接入方提供 | 平台校验 |
| --- | --- | --- |
| 识别业务 | 业务类型、稳定记录ID、展示编号、基地/权限上下文 | 类型已注册，记录存在且可访问；展示编号不替代内部ID |
| 读取与字段说明 | 字段类型、标签、明细结构、可写边界、字段版本、数据 | 节点权限只能收紧业务和角色权限；客户端不能改元数据 |
| 发起校验 | 该业务真正需要的必填、取值和可发起条件 | 使用服务端当前数据，失败不生成实例和持久化占用 |
| 写入与流程占用 | 受控补丁、业务可编辑性、版本、可回滚写入 | 无权字段不能修改；旧页和并发请求不能绕过；多流程占用不误释放 |
| 完成/终止处理 | 可选的、明确注册的状态变更或归档动作 | 没有配置时不猜业务状态；动作失败不得假报流程成功 |
| 打印数据 | 数据对象、字段/明细说明、版本和适用模板 | 模板与数据源匹配；缺失绑定和无权限数据有明确处理 |

实施顺序：

1. 将协议读取、发起校验、写入、占用判断封装为接入边界，保持旧接口和历史实例可读；覆盖原有协议回归用例。
2. 由同一接入元数据提供选择项、字段及页面入口，再替换发起页、节点表单和权限中的固定映射；未接入的业务继续阻止发布。
3. 将业务可编辑规则与流程占用分离，整理演示状态字典和旧列表审核入口；按角色、当前任务及多流程情形验证。
4. 给打印提供独立的数据源说明和数据对象，保留旧模板及分页引擎；不批量改名已有字段、模板或存档。
5. 用第二个简单业务验证端到端复用，再安排正式系统接口、业务完成策略及生产存储。

在事务改造前不声称业务写入、流程写入、日志在文件存储中已经达到数据库同事务保证。生产接入必须定义失败重试、幂等和回滚办法。

| V01 | 保存、重新打开带条件及驳回线的流程，并发布新版本 | 图和配置一致，问题能定位到节点；老实例不切到新版本 |
| V02 | A填报，B审核；设置某字段只读、某字段隐藏 | 页面和服务端一致；伪造请求不能写只读值或读取隐藏值 |
| V03 | 同一任务打开两个旧页面，重复提交和并发办理 | 只成功一次，旧版本明确提示冲突，无重复待办 |
| V04 | B驳回，A在退回节点修改重提 | 资料保存成功，路径符合配置，意见和办理人完整留痕 |
| V05 | 审核中从普通详情整页/分模块保存、批量提交、列表审核及删除 | 全部后端入口执行当前权限和占用规则，混合批量无部分误写 |
| V06 | 同记录含多个历史完成/终止实例，并另有运行或挂起实例 | 活跃实例仍限制编辑；全部释放后按业务接入策略恢复，不清除历史 |
| V07 | 完成普通测试流程，检查业务状态；再执行明确配置的测试业务动作 | 默认结束不猜业务状态；配置动作仅改白名单目标且失败可回滚 |
| V08 | 使用独立测试业务：名称、申请金额、物品明细，无房屋和签约字段 | 可发起、办理、驳回重提；不要求房屋地址；不借用协议明细存储 |
| V09 | 为V08绑定字段、明细、页码，使用空数据及多页数据预览、打印 | 保存重开绑定一致；无协议假数据；文字不丢失、明细分页正确 |
| V10 | 修改共用页面或表单模板，再查看旧流程实例及已有打印模板 | 发布快照和已有模板不被静默改写，当前资料与审批快照含义清楚 |
| V11 | 保存配置、业务数据、实例和模板，重启服务并清理可再生构建产物 | 数据保留，来源目录明确，损坏存档不被演示种子覆盖 |
| V12 | 按真实样张打印/PDF，核对纸张、字体、换行、分页和长明细 | 使用实际输出验收，不能只以模板JSON或预览截图判定通过 |

## 8. 真正需要补充的业务信息

平台边界盘点无需等待这些答案；接入正式业务时再逐项落实：

1. 真实业务记录从哪里读取/保存，稳定ID、字段说明和权限接口是什么？
2. 哪些流程只是审核一段资料，哪些流程有明确业务完成动作？状态字典由哪个系统维护？
3. 流程结束后查看、打印需要当前数据还是审批时的数据？是否需要版本、更正或归档？
4. 打印的真实样张、纸张、明细、数据来源、历史模板兼容和精度要求是什么？
5. 当前验收目标是本地演示，还是包含旧系统菜单、待办、消息、数据库和正式组织权限集成？

已交付范围基线、代码证据、整改顺序和验收清单，并完成正文编辑规则修正及演示状态展示字典统一。接入接口实施、旧审核路径整理、第二样例和真实系统联调仍属于后续明确列出的整改工作。
